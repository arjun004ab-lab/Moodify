# Moodify 100/100 Cloud & Research Upgrade

This package is a competition-oriented hardening layer over the existing Moodify build.

## What is upgraded

1. Cloud-ready PostgreSQL database configuration.
2. Production CORS from `MOODIFY_FRONTEND_ORIGINS`.
3. `/health/live` and `/health/ready` endpoints.
4. Structured request logging.
5. Model metadata and SHA-256 endpoint.
6. Real held-out CNN evaluation script.
7. Research Evidence Console in React.
8. Backend CI/CD workflow.
9. Static frontend CI/CD workflow.
10. Docker health/readiness design.
11. Explicit responsible-AI and evaluation framing.

## Critical truthfulness rule

Do not type accuracy/F1 numbers into the frontend.

Run `backend/evaluate_model.py` against a REAL held-out image test set. It creates
`backend/model_metrics.json`, and the Research page then displays those measured values.

If you do not have a held-out image test set, the dashboard intentionally says:
"Evaluation not yet performed."

## Current AI boundary

- Emotion: trained CNN model (`emotion_cnn.h5`)
- Face preprocessing: OpenCV classical computer vision
- Beauty Scan: current visual-proxy logic, not a trained beauty ML model
- Music: deterministic emotion-to-track mapping, not a learned recommender

## Important database migration note

`Base.metadata.create_all()` is acceptable for a prototype bootstrap.
For production evolution, use Alembic migrations so schema changes are explicit,
reviewable and reversible.

## Evaluation command

From D:\moodify\backend:

    python -m pip install -r requirements-evaluation.txt

Then:

    python evaluate_model.py --dataset-root ..\evaluation_data\test

The directory must contain one folder per class:

    evaluation_data/test/
      angry/
      disgust/
      fear/
      happy/
      sad/
      surprise/
      neutral/

The test set should be held out from training/model selection.

## Recommended competition evidence

Have these on one research slide:

- Test-set sample count
- Accuracy
- Macro precision
- Macro recall
- Macro F1
- Confusion matrix
- Mean inference latency
- Exact model input shape
- Exact model version/hash

Never invent a metric.

## Security hardening before public deployment

- Use HTTPS only.
- Restrict CORS to the exact production frontend.
- Use a strong random `MOODIFY_SECRET_KEY`.
- Store secrets in Azure secret/configuration services, not Git.
- Restrict PostgreSQL network access in production.
- Add backups and database migration management.
- Define camera-image retention/deletion policy.
- Log only sanitized metadata; do not log raw face images.
- Review model bias/fairness on appropriate held-out cohorts.
